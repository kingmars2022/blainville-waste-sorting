# Review of the Redis and sorting assistant changes

Reviewed baseline: `41e4368` on
`claude/blainville-waste-sorting-review-pqbsbz`. At review time, remote `main`
still pointed to `2ec30d6`; the new features were not merged into it.

## Findings and repairs

1. **Quota counters could be evicted (high).** Compose used `allkeys-lru` for
   an instance shared by caches and assistant rate limits. Counter eviction
   silently restores a caller's quota. Changed to `noeviction`: at capacity,
   cache errors fall through, while quota errors reject assistant requests.
2. **Quota expiry was not atomic (medium).** Separate `INCR` and `EXPIRE`
   commands could leave permanent keys after interruption. A single Lua script
   now increments and installs missing expiry atomically. Null/invalid results
   fail closed. UTC hourly keys avoid daylight-saving ambiguity.
3. **Language changes retained stale answers (medium).** The sorting page kept
   an old-language answer and accepted in-flight responses after a language
   switch. A request generation counter now clears old state and ignores stale
   completions, including errors and pending-state updates.
4. **Fallback responses were attributed to Claude (medium).** The configured
   provider was reported even when the template generated the answer. Provider
   metadata now travels with each composition. No-context refusals are marked
   as template responses, without calling the model.
5. **Incomplete model responses were accepted (medium).** The composer only
   rejected explicit refusals and empty content. It now requires `end_turn`;
   other stop reasons, including output truncation, fall back to guide text.
   The client also has an explicit 15-second timeout and zero automatic retries.
6. **Documentation overstated guarantees.** README now distinguishes a
   retrieval match from verified correctness, records the small development
   evaluation's limits, and explains Redis dependency and budget limitations.

## Important limitations still present

- A relative score threshold cannot detect an irrelevant top hit: the best
  positive score always passes its own relative cutoff. Nonempty context is
  not proof that the entry covers the question. Expand evaluation with unseen
  materials, overlapping words, negation, multi-item questions and Chinese
  false positives before claiming broader accuracy.
- The Claude response is free text. Prompt instructions and citations do not
  mechanically enforce every claim or prevent prompt injection. The default
  template avoids generated disposal rules but can still quote a wrong match.
- The 18-question set was used during tuning; 12/12 and 6/6 are development
  results, not generalization estimates. This review did not reproduce the
  historical cache benchmarks or the full-text evaluation.
- Per-IP limits do not bound total spending across callers. Redis persistence
  is off in local Compose, so restart resets limits. Public paid deployments
  need an application-wide budget policy and provider spending controls.
- Behind a reverse proxy, `getRemoteAddr()` can identify the proxy instead of
  the resident. Configure the actual trusted proxy boundary before deployment;
  accepting arbitrary forwarded headers would enable quota bypass.
- Resident sorting cards still use static frontend data, while the assistant
  and admin use MySQL. This predates these changes and needs a separate data
  migration: the static cards include seasonal information and examples that
  must be preserved when moving them into the database.

## Assessment of proposed additions

- **Redis:** reasonable for shared schedule and notice reads. Retain measured
  benchmarks with their workload, environment, warm-cache state and limitations.
- **RAG:** reasonable as an optional guide-search assistant. The default
  template mode is retrieval with deterministic rendering; Claude mode adds
  generative answering. An agent is not automatically a better successor.
- **MongoDB:** heterogeneous audit snapshots alone do not justify another
  database. MySQL supports a native JSON type. An audit table can store actor,
  action, time and JSON snapshots in the same transaction as the business write.
  Append-only behavior depends on permissions and application design, not on
  choosing a document store. [MySQL JSON documentation](https://dev.mysql.com/doc/refman/8.4/en/json.html).
- **Kafka:** two consumers alone do not establish a need for Kafka. For this
  app, a MySQL outbox and a worker are a simpler starting point. A future broker
  design must address database/event atomicity, duplicate delivery, idempotency
  and retries before claiming reliable notifications or audit coverage.
- **AWS:** S3 uploads and Lambda image processing are plausible if image
  support is actually needed. A separate API Gateway metadata service should
  have its own requirement; image processing alone does not require it. Validate
  upload type/size, untrusted image decoding, event retries and output-prefix
  isolation. Free-tier eligibility varies by account and plan; do not promise
  zero cost from fixed service quotas. [AWS free-tier changes](https://aws.amazon.com/about-aws/whats-new/2025/07/aws-free-tier-credits-month-free-plan/).
- **Admin agent:** prioritize drafting and preview. Approval must bind to a
  concrete operation and payload, with server-side authorization, validation,
  audit and protection against repeated execution. Internship dates are not a
  technical reason to choose agents over question answering.
